# TS-13: Recruiter Settings page

- **Status:** Done
- **Owner:** Moazzam (frontend)
- **Depends on:** US-01, US-02, US-03, TS-07
- **Branch:** `feature/TS-13-settings-page`

## Why this exists

The sidebar had a "Settings" nav item with no route behind it, permanently
disabled ("Coming soon"). Requested directly while cleaning up dead sidebar
items — every recruiter needs somewhere to manage their own account and Google
connection, and the app already has the backend pieces for it
(`PATCH /recruiters/me`, `account_state`, the reconnect flow) with nowhere to
surface them outside a `REAUTH_REQUIRED` banner.

## Story

As a recruiter, I want a Settings page to edit my name, see my Google
connection status, and reconnect if it's expired, so I'm not stuck relying on
a warning banner as the only way to fix my account.

## Acceptance criteria

- [x] `/settings` route, reachable from the sidebar (previously a disabled
      placeholder with no `to`).
- [x] Account card: edit full name (`PATCH /api/v1/recruiters/me`, already
      existed — `backend/app/api/routes/recruiters.py`), email shown
      read-only, sign-out button (reuses the existing `useLogout()`).
- [x] Google connection card: shows connected vs. `REAUTH_REQUIRED`, with a
      "Reconnect Google" button when expired (reuses the existing
      `googleReconnectUrl` — the same link `AppShell`'s banner already uses).
- [x] Interview availability card: links to `/scheduling` rather than
      duplicating `AvailabilityForm`, which already owns that UI.
- [x] Save button disabled until the name actually changes; loading and error
      states on save (inline field error, matching every other form in the app).

## Notes

No backend or schema changes — every piece of data and every mutation this
page needs already existed. New frontend-only: `useUpdateRecruiter()` in
`lib/auth.ts` (the only missing hook, for the existing `PATCH` route),
`pages/Settings.tsx`, one route, one sidebar link.

## Out of scope

Notification preferences, application branding/company name (no such field
exists on `Recruiter` today — would need a migration, not bundled into this
story), theme/appearance settings (no dark mode yet — see `mobile/README.md`'s
same note).
