# US-02: Login, session, and profile

- **Status:** Done
- **Epic:** EP-01
- **Points:** 3
- **Backend:** Moazzam · **Frontend:** Saif
- **Depends on:** US-01

## Story
As a recruiter, I want to see my profile and log out, so that I can confirm which
Google account AutoHire is acting as and end my session on a shared machine.

## Note on size
US-01 already built the session cookie, `get_current_recruiter`, and `GET /auth/me`.
This story is the remainder: logout, and profile read/update. It is small on purpose —
do not expand it. Anything about *expired* tokens belongs to US-03.

## Acceptance criteria
- [x] `POST /api/v1/auth/logout` clears the session cookie (same name, path, and
      attributes as set — a mismatch silently fails to clear) and returns 204
- [x] Logout is idempotent: calling it without a session returns 204, not 401
- [x] `PATCH /api/v1/recruiters/me` updates `full_name` only; email, `google_user_id`,
      tokens, and `account_state` are not writable through this route
- [x] `last_login_at` is updated on each successful callback (US-01 set the column;
      confirm it is actually being written)
- [x] All recruiter routes 401 without a valid session cookie
- [x] `GET /auth/me` response includes `account_state` so the frontend can render the
      reconnect banner in US-03 without a second call

## Additions decided after this story was written
- [x] `RecruiterOut` (`/auth/me`) now includes `granted_scopes` — `docs/api-contract.md`
      already promised it; Saif needs it to name which permission is missing in the
      reconnect banner. `RecruiterUpdate` uses `extra="forbid"` (a 422 on `email`/
      `account_state`, not a silent drop) — a caller finds out at the call site, not
      three sprints later.
- [x] `last_login_at` confirmed already written correctly since US-01
      (`app/services/auth_service.py::upsert_recruiter`); it had no test, so one was
      added rather than left unverified.

## Test cases
| ID | Scenario | Expected |
|---|---|---|
| TC-01 | Logout with valid session | 204, cookie cleared, subsequent `/auth/me` → 401 |
| TC-02 | Logout with no session | 204, no error |
| TC-03 | PATCH `full_name` | 200, name changed, other fields untouched |
| TC-04 | PATCH attempting `email` or `account_state` | Field ignored or 422 — never applied |
| TC-05 | Any recruiter route without cookie | 401 |

## Out of scope
Token refresh and reconnect (US-03). Account deletion. Password anything — there are
no passwords in this system.
