# US-12: Candidate submits an application

- **Status:** Todo
- **Epic:** EP-03
- **Points:** 8
- **Owner:** Saif
- **Depends on:** US-06, US-11

## Story
As a candidate, I want to fill in the application form and upload my resume, so that
I can apply without creating an account.

## Acceptance criteria
- [ ] The form renders dynamically from `template_fields` (all 7 field types)
- [ ] Required fields are enforced client-side and server-side
- [ ] Resume accepts PDF and DOCX only, validated by **magic bytes**, not extension
- [ ] Files over `MAX_RESUME_MB` are rejected with a clear message
- [ ] On success: `candidates` row + one `candidate_form_responses` row per answered field
- [ ] Resume stored via `ResumeStore`; `resume_drive_file_id` / `resume_storage_key` set
- [ ] `submission_status = SUBMITTED`
- [ ] Re-applying with the same email to the same job returns 409 DUPLICATE_SUBMISSION
- [ ] Submitting to an expired or closed job returns 410 JOB_EXPIRED
- [ ] Confirmation screen shown; no Google account required at any point

## Notes
- `POST /api/v1/public/apply/{slug}` — multipart, **unauthenticated**
- Rate limit per IP. This and `GET` on the same path are the only open endpoints
  in the system; treat them as hostile input.
- Write the candidate row and responses in one transaction. Store the file first;
  if the DB write then fails, the orphan file is cleaned by a sweeper — an orphan
  file is recoverable, a candidate row pointing at a missing resume is not.

## Out of scope
The confirmation email itself (US-14). AI processing (US-15).
