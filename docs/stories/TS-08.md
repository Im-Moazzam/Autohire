- **Status:** In progress — D-01, D-02, D-06 done; D-03/D-04/D-05 blocked, see summary
- **Owner:** Moazzam (code), Nimra (document editing)
- **Depends on:** TS-06 and TS-07 merged — the documents should describe the *final*
  system, so this runs last
- **Branch:** `feat/TS-08-docs-reconciliation`

## Why this exists

The submitted SDS and RS still describe an architecture that was formally reversed.
`docs/drift.md` records every reversal with sound reasoning — it is the best artifact
in the repository — but **nothing in the SDS points at it.** An examiner reading the
SDS cold sees a system that does not exist, and the document that explains why is
invisible to them.

Separately, `make docs` is supposed to regenerate the ERD, OpenAPI, class diagram and
test report from the live system. **One of those four silently produces an empty
file.** That undercuts the whole "code is the source of truth" position.

## D-01 — `make docs-erd` produces an empty diagram  🔴

`backend/app/scripts/dump_erd.py` imports only `app.core.db.Base`. No model module is
ever executed, so `Base.metadata` is empty and the script emits:

```
@startuml
@enduml
```

`dump_openapi.py` works only because it imports `app.main`, which transitively imports
every model.

**Repro:** `docker compose exec -T api python -m app.scripts.dump_erd` — confirm the
output is two lines *(verified by the review: it is)*.

**Fix:**
- Add `import app.models  # noqa: F401` before reading `Base.metadata`. Confirms 12
  tables and 20 foreign keys become visible.
- The script emits no relationships at all — even fixed, it produces a table list, not
  an ERD. Emit the foreign-key edges too (`table }o--|| other` style), plus
  nullability and PK/FK markers, so the generated diagram is actually comparable to the
  hand-drawn one in the submission.
- The Makefile comment claims the ERD is rendered "from the live database". It is
  rendered from the SQLAlchemy metadata. Either correct the comment or reflect against
  the real database — pick one and say which.

**Prove it:** regenerate, confirm all 12 tables and the FK edges appear, render it, and
commit the rendered output alongside.

**Fix — the approach matters more than the edits.** Do **not** silently rewrite history
to make the SDS look like it was always right. That destroys the thing that makes
`drift.md` valuable. Instead:

1. **Add a front-matter section, "Deviations from the submitted SDS."** One page. State
   plainly that the SDS was written before implementation, that every deviation was
   recorded with reasoning at the time it was made, and that `docs/drift.md` is the
   revision history. Summarise the four or five architecturally significant reversals —
   Pinecone → pgvector, Google Forms → self-hosted apply, OpenAI → fastembed,
   per-adapter cloud switch — each with its drift row number.
2. **Mark each affected passage in place** with a short inline note: *"Superseded — see
   docs/drift.md row N"*. Do not delete the original text. The superseded claim plus the
   reasoned correction is a stronger artifact than a clean document, and it is honest.
3. **Fix the outright factual errors** where there was never a decision, only a
   drafting mistake: the `api_name_enum` member list, `is_accepting_responses`'s
   default, `pinecone_vector_id` → `vector_id`, `google_form_id`'s NOT NULL. These
   are wrong, not superseded — correct them and note the correction.
4. **Replace the schema section's tables** with the output of the fixed D-01 generator,
   so the document's ERD is provably the built one.

## D-05 — Verify the document file format  🟡

`file` reports both `.docx` files as **"Unicode text, UTF-8 text"**, not a ZIP/OOXML
package, and the content is markdown (`**bold**`, `|` tables). This is most likely an
artifact of how the Projects uploader extracted them — **check the originals on
Moazzam's machine before concluding anything.** But if the files in the repo really are
markdown renamed to `.docx`, Word will not open them and a submission portal may reject
them. Thirty seconds to verify, and expensive to discover at submission time.
