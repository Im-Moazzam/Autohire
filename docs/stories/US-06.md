# US-06: Launch a job posting

- **Status:** Done
- **Epic:** EP-02
- **Points:** 13
- **Backend:** Moazzam · **Frontend:** Saif
- **Depends on:** US-01, US-03, US-04, TS-02

> Rewritten 2026-08-12. The original version predated TS-02 and ADR-004. Two changes:
> cross-tenant is **404, not 403** (ADR-004 P8, as US-04 implements), and the JD
> embedding moved to US-18. See "Scope decisions" below.

## Story
As a recruiter, I want to launch a job by entering a description, choosing a template
and setting an expiry, so that I get a shareable application link without building a
form by hand.

## What this story is
`/api/v1/jobs` already exists as TS-02 stubs. This story replaces the fixtures with
real persistence — **response shapes must not change**, Saif is building against them.
A wrong shape is a `drift.md` row plus a regenerated client, never a silent edit.

Reuse US-04's patterns directly: service holds the logic, ownership-scoped queries,
soft delete, one transaction per write.

This is also **the first route that calls `google_call`** — the real end-to-end
exercise of the US-03 wrapper, and the first resource adapter (`ResumeStore`).

## Scope decisions
1. **JD embedding is deferred to US-18.** The original AC required a `JD_EMBEDDING`
   background task, which needs the `background_tasks` table, Celery wiring, and an
   embedding adapter — none of which exist. `jd_embedding_id` stays NULL here and
   US-18 populates it when embeddings are actually built. Log as a `drift.md` row.
2. **Cross-tenant returns 404, not 403** (ADR-004 P8). The original story's
   `TENANT_FORBIDDEN` is stale — do not implement it.
3. **`TEMPLATE_IN_USE` gets wired up here.** US-04 declared the 409 on
   `DELETE /templates/{id}` but couldn't check it (drift row 27). Now `job_postings`
   exists, so implement the check and close that gap.

## Acceptance criteria
- [x] Migration creates `job_postings` per `docs/schema.md`, including
      `job_status_enum`, UNIQUE on `apply_slug`, index on `(recruiter_id, status)`,
      and the partial index on `expires_at WHERE status = 'LIVE'`
- [x] `POST /jobs` requires job title, JD, `template_id`, and `expires_at`
- [x] `expires_at` in the past is rejected with 422; no row created
- [x] `template_id` must belong to the calling recruiter and not be soft-deleted —
      404 otherwise (not 403)
- [x] `apply_slug` is `secrets.token_urlsafe(12)`, unique, retried on collision,
      and is **not** derived from the job UUID
- [x] A resume folder is created via the `ResumeStore` adapter and its ID stored:
      Google Drive folder in cloud mode, `./storage/resumes/{job_id}/` in local mode
- [x] **Ordering:** the job row commits first with `status = DRAFT` and
      `google_drive_folder_id = NULL`, *then* the folder is created, *then* the row
      updates to `status = LIVE` with the folder ID. No DB transaction is held open
      across a network call to Google.
- [x] If folder creation fails, the job remains `DRAFT`, the error surfaces, and the
      operation is retryable — no orphaned or half-created job. `RESUME_FOLDER_FAILED`
      is 502 in cloud mode (an upstream/Drive failure) and 500 in local mode (our own
      filesystem failed, not an upstream)
- [x] `JobOut.apply_url` is computed server-side from `PUBLIC_APPLY_BASE_URL` +
      `apply_slug`; the frontend never assembles it
- [x] `google_form_id` / `google_form_url` remain NULL (ADR-001)
- [x] `jd_embedding_id` remains NULL (deferred, see Scope decisions)
- [x] `PATCH /jobs/{job_id}` `{"status": "CLOSED"}` sets `is_accepting_responses = false`
      and `status = CLOSED` — no `/close` action endpoint (ADR-004 P3, drift row 21)
- [x] `PATCH /jobs/{job_id}` `{"status": "LIVE"}` on a `DRAFT` job retries the launch —
      runs the same `finalize_launch` as create, does not mint a new `apply_slug`
- [x] `DELETE /templates/{id}` now returns 409 `TEMPLATE_IN_USE` when a non-deleted
      job posting references that template

## The ResumeStore adapter
First resource adapter. This pattern gets copied by Gmail (US-27) and Calendar
(US-26), so build it with the same care US-03 got.

```python
class ResumeStore(Protocol):
    def create_job_folder(self, recruiter: Recruiter, job_id: UUID, name: str) -> str: ...
```

- `LocalResumeStore` — `mkdir ./storage/resumes/{job_id}/`, returns the path
- `DriveResumeStore` — goes through `google_call(...)`, **never** `googleapiclient`
  or raw httpx
- Selected by `APP_ENV` (ADR-003). Default local; cloud cutover is a later slice.
- Only the file-upload half (US-12) is missing from the Protocol — add
  `store_resume(...)` there, not here.

## Test cases
| ID | Scenario | Expected |
|---|---|---|
| TC-01 | Valid title + JD + template + future expiry | 201, status LIVE, slug present, folder created |
| TC-02 | `expires_at` in the past | 422, no row created |
| TC-03 | `template_id` belonging to another recruiter | 404, no row created |
| TC-04 | `template_id` that is soft-deleted | 404 |
| TC-05 | Folder creation raises | Job persists as DRAFT with NULL folder id, error returned; retry via `PATCH {"status":"LIVE"}` succeeds with the **same `apply_slug`** |
| TC-06 | Two jobs launched in succession | Slugs differ, no collision |
| TC-07 | Slug generator collides once (mocked) | Retries, succeeds, one row |
| TC-08 | `GET /jobs/{id}` for another recruiter's job | 404 |
| TC-09 | `PATCH /jobs/{id}` `{"status":"CLOSED"}` | `status` CLOSED, `is_accepting_responses` false |
| TC-10 | `DELETE` a template referenced by a live job | 409 `TEMPLATE_IN_USE` |
| TC-11 | `DELETE` a template whose only job is soft-deleted | 204 — the reference doesn't count |
| TC-12 | `GET /jobs` | Only the caller's non-deleted jobs |
| — | `google_call` invoked in cloud mode | Goes through the wrapper, one `api_usage_logs` row |

TC-05 is the important one — it proves the ordering AC. Mock the store to raise, then
assert the job row exists as DRAFT, and that the retry does not regenerate `apply_slug`
(a link already shared from the failed attempt must not silently die).

## Out of scope
Editing, TTL extend/revoke, delete (US-09, US-10). Expiry automation / `ExpiryMonitor`
(US-08). JD embedding (US-18). Resume upload (US-12). Any frontend — Saif owns the
launch form, the copy button, and the dashboard card.

## Note
`submission_count` on `JobOut` should be a `COUNT` subquery or a joined aggregate, not
a Python-side `len()` over loaded candidates — that's the unbounded-query defect class
`CLAUDE.md` names, and candidates arrive in the hundreds.
