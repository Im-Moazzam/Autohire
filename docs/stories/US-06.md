# US-06: Launch a job posting

- **Status:** Todo
- **Epic:** EP-02
- **Points:** 13
- **Owner:** Moazzam
- **Depends on:** US-01, US-04

## Story
As a recruiter, I want to launch a job by entering a description, choosing a template
and setting an expiry, so that I get a shareable application link without building a
form by hand.

## Acceptance criteria
- [ ] Form takes job title, JD, template, and TTL (expiry date/time)
- [ ] TTL must be in the future; past or malformed values are rejected inline
- [ ] On submit, a `job_postings` row is created with `status = LIVE`
- [ ] A unique random `apply_slug` (16 chars) is generated — **not** the job UUID
- [ ] A Google Drive folder is created for the job and its ID stored
      (local mode: a `./storage/resumes/{job_id}/` directory)
- [ ] The JD is embedded and `jd_embedding_id` stored, via a `JD_EMBEDDING` background task
- [ ] The full apply URL is shown with a copy button
- [ ] The new job appears on the dashboard as an active card
- [ ] `google_form_id` / `google_form_url` remain NULL (ADR-001)

## Test cases
| ID | Scenario | Expected |
|---|---|---|
| TC-07 | Valid JD + template + TTL | Job created, application link generated |
| TC-08 | TTL in the past | Inline validation error, no row created |
| — | Drive folder creation fails | Job saved as DRAFT, error surfaced, retryable |
| — | Two jobs launched in succession | Slugs differ; no collision |
| — | Another recruiter requests the job by ID | 403 TENANT_FORBIDDEN |

## Notes
- `POST /api/v1/jobs`
- Drive folder creation goes through `ResumeStore`, never `googleapiclient` directly
- Embedding is async — the job is usable immediately; ranking just can't run until it lands
- Slug generation: `secrets.token_urlsafe(12)`, retry on unique violation

## Out of scope
Editing, TTL extend/revoke, delete (US-09, US-10). Expiry automation (ExpiryMonitor)
lands with US-08.
