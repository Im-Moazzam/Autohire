# TS-12: Frontend UI/UX consistency and polish pass

- **Status:** Done
- **Owner:** Moazzam (frontend)
- **Depends on:** TS-10, US-13, US-18-19, US-26-27
- **Branch:** `feature/TS-12-frontend-ui-polish`

## Why this exists

Requested directly, not from the RS/SDS baseline. After TS-10/TS-11 the web
frontend was functionally complete but had accumulated inconsistencies typical
of a fast-moving two-person build: a fragmented icon system, missing hover
transitions, a layout bug that made the ranked-candidates action buttons
render at wildly different widths, and a card grid with no height stretching.
Backfills a story file per this project's convention of not shipping UI
changes without one (see TS-09, TS-10).

## Story

As a recruiter, I want the app's buttons, cards, icons, and hover states to
behave consistently across every screen, so the product reads as one
considered system instead of a collection of screens built at different times.

## Acceptance criteria

- [x] Icon set consolidated into `components/ui/icons.tsx` as the single
      source — `Sidebar.tsx` and `Home.tsx` previously duplicated 5+ icons
      byte-for-byte instead of importing them.
- [x] The AutoHire logo mark (previously inlined 3 separate times, one copy
      with a broken-indentation artifact) extracted to a shared
      `components/app/Logo.tsx`.
- [x] `DataTable` rows no longer show a hover highlight when the table has no
      `onRowClick` — was a misleading affordance on Emails/Templates/Scheduling.
- [x] Every `<button>` in the app shows a pointer cursor on hover (global
      `tokens.css` rule — `<button>` has no pointer cursor by default and
      nothing was setting it, including the shared `Button` component).
- [x] Every text-hover link (`hover:underline` / `hover:text-ink`) transitions
      smoothly instead of snapping instantly — was inconsistent across 7 files.
- [x] `TemplateBuilder`'s field-reorder controls use icons
      (`ArrowUpIcon`/`ArrowDownIcon`/`TrashIcon`) instead of raw `↑`/`↓`
      characters, and the "Required" checkbox is styled instead of unstyled
      browser-default.
- [x] `AppShell`'s API-unreachable "Retry" button uses the shared
      `buttonClassName()` instead of a hardcoded, hover-less one-off.
- [x] Dashboard KPI and donut-chart cards stretch to equal height within
      their grid row (`h-full` through the `Link`/`Card` chain) — previously
      the "Jobs" card (more status-breakdown chips) rendered visibly taller
      than its siblings.
- [x] `StatusActions` (Schedule interview / Reject / Undo) no longer
      double-wraps its buttons in a nested flex container — was making the
      Schedule button stretch to fill the row while Reject/Undo collapsed to
      a cramped inner width, in both the candidate profile modal and the
      ranked-candidates cards.
- [x] Ranked-candidates list uses a responsive 2-column grid
      (`grid-cols-1 lg:grid-cols-2`) instead of one full-width row per
      candidate.
- [x] `RankedCard` reworked: status badge on its own line (was crowding the
      name and could wrap mid-pill), resume link is an icon button instead of
      a text link crowding the header, `MatchScore` accepts a `className`
      override so it can span the card's full width instead of a fixed
      160px strip, visual dividers separate header / AI assessment / skills /
      actions, and actions are pinned to the card's bottom (`mt-auto`) so they
      align consistently across a stretched grid row. No information removed.

## Notes

Pure frontend styling/layout changes — no API contract, schema, or route
changes. `MatchScore`'s new `className` prop defaults to the previous
`w-40`, so its other caller (`KitchenSink.tsx`) is unaffected.

## Out of scope

A shared design-tokens package between `frontend/` and `mobile/` (both hand-sync
against `docs/design.md` today) — noted as a known gap in `mobile/README.md`,
not addressed here.
