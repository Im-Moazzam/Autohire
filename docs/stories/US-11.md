# US-11: Candidate opens the public application link

- **Status:** Done
- **Epic:** EP-03
- **Points:** 5
- **Backend:** Moazzam · **Frontend:** Saif
- **Depends on:** US-04, US-06, TS-02

## Story
As a candidate, I want to open the link a recruiter shared and see the application
form, so that I can apply without creating an account or signing in to anything.

## What this story is
`GET /api/v1/apply/{apply_slug}` already exists as a TS-02 stub reading
`fixtures.JOBS`. This story makes it real. It is small — a single unauthenticated
read — but it is the **first public endpoint in the system**, so the exposure rules
matter more than the logic.

No migration. `candidates` arrives in US-12.

## The security boundary
This endpoint has **no session, no recruiter, no auth dependency**. Anyone with the
link can call it. Two consequences:

- **`PublicJobOut` exposes only** `job_title`, `job_description`, `fields`,
  `is_accepting_responses`, `expires_at`. No `job_id`, no `recruiter_id`, no
  `template_id`, no `submission_count`, no recruiter name or email. Returning an
  internal UUID here would let a candidate enumerate or correlate postings.
- The lookup is **by `apply_slug` only**, never by `job_id`. That is the entire point
  of the slug existing (US-06).

## Acceptance criteria
- [x] `GET /apply/{apply_slug}` returns `PublicJobOut` for a LIVE, accepting,
      unexpired job — no auth required
- [x] The template's fields are included, ordered by `field_order`, with `options`
      populated for `MULTIPLE_CHOICE` / `DROPDOWN`
- [x] Unknown slug → **404**
- [x] Soft-deleted job → **404** (indistinguishable from unknown)
- [x] DRAFT job → **404**. A draft is not public; revealing it would leak an unlaunched
      posting.
- [x] CLOSED job, `is_accepting_responses = false`, or `now >= expires_at` → **410 Gone**
      with `JOB_CLOSED`, and the body still carries `job_title` so the frontend can say
      *which* posting closed rather than showing a bare error
- [x] Response contains no recruiter-identifying field and no internal UUID —
      assert this explicitly in a test
- [x] Endpoint works with no session cookie present at all

## Test cases
| ID | Scenario | Expected |
|---|---|---|
| TC-01 | LIVE, accepting, unexpired | 200, fields in `field_order`, options present |
| TC-02 | Unknown slug | 404 |
| TC-03 | Soft-deleted job | 404 |
| TC-04 | DRAFT job | 404 |
| TC-05 | CLOSED job | 410 `JOB_CLOSED`, `job_title` present |
| TC-06 | `is_accepting_responses = false` | 410 |
| TC-07 | `expires_at` in the past, status still LIVE | 410 — expiry is evaluated at read time, not by a background job (US-08 owns the status transition) |
| TC-08 | Response body inspected | No `job_id`, `recruiter_id`, `template_id`, or recruiter fields |
| TC-09 | Request with no cookies | 200, works normally |

TC-07 matters: US-06 deliberately leaves an expired job as LIVE. Acceptance is
`LIVE AND is_accepting_responses AND now < expires_at`, evaluated per request.

## Note
Put the three-condition acceptance check in **one** service function
(`job_service.assert_job_accepting(...)` or similar). US-12 needs the identical check
before writing a submission, and two copies will drift.

**Resolved during implementation:**
- AC "no internal UUID" is slightly overbroad against TC-08's actual list (`job_id`,
  `recruiter_id`, `template_id`, `submission_count`). `TemplateFieldOut.field_id`
  deliberately survives — `candidate_form_responses.field_id` is an FK, so US-12's
  submission payload has to key answers by it; there's no other stable identifier.
  It names a form field, not a tenant/job/recruiter, and isn't enumerable without
  the slug. TC-08 is what's authoritative; `field_id` is not in its list.
- Error code consolidated to a single 410 `JOB_CLOSED` with
  `details: {job_title, reason}` (`reason` ∈ `CLOSED | EXPIRED | PAUSED`), replacing
  the earlier `JOB_EXPIRED`/`JOB_NOT_ACCEPTING` split already in `docs/api-contract.md`
  from the TS-02 stub. See `docs/drift.md` rows 30–31.

## Out of scope
Submitting the form (US-12). Any frontend — Saif owns `/apply/{slug}`. Rate limiting.
