# TS-09: Reopen a closed job

- **Status:** Done
- **Owner:** Saif (frontend + backend, PR #38)
- **Depends on:** US-06
- **Branch:** `feat/US-06-reopen-closed-job` (merged to `dev` as PR #38)

## Why this exists

Shipped under the `US-06` story ID, but `US-06` ("Launch a job posting") was
already `Done` and describes none of this. There was no story file with
acceptance criteria for reopening — this backfills one from the implemented
behaviour so the feature has a real DoD, per code review of PR #38
(`docs/drift.md` row 70 already records the design rationale).

## Story
As a recruiter, I want to reopen a job I closed so that I can extend the
deadline and keep accepting applications without losing the original
`apply_slug` link every candidate and job board already has.

## Acceptance criteria
- [x] `CLOSED -> LIVE` is a legal transition; every other transition set is
      unchanged (`PROCESSED -> LIVE` stays illegal — a processed job already
      has ranked/invited/scheduled candidates a fresh applicant pool would
      need a re-ranking story to reconcile with).
- [x] Reopening requires a future `expires_at` — the payload's if provided,
      else the job's existing one — or 409s `REOPEN_REQUIRES_FUTURE_EXPIRY`.
- [x] A successful reopen sets `is_accepting_responses = True`.
- [x] `JobBuilder.tsx` surfaces a "Reopen job" action on a `CLOSED` job,
      reusing the existing "Application deadline" field and its client-side
      future-date validation.

## Test cases
| ID | Scenario | Expected |
|---|---|---|
| TC-01 | Reopen with an explicit future `expires_at` | 200, `status: LIVE`, `is_accepting_responses: True` |
| TC-02 | Reopen keeping an already-future `expires_at` | 200, same as above, deadline unchanged |
| TC-03 | Reopen a job whose `expires_at` is in the past, no new date supplied | 409 `REOPEN_REQUIRES_FUTURE_EXPIRY` |
| TC-04 | Reopen a `PROCESSED` job | 409, transition still illegal |

## Notes
No schema change (`status` and `expires_at` already existed). See
`docs/drift.md` row 70 for the full design rationale.

## Out of scope
Reopening a `PROCESSED` job — needs a re-ranking story of its own to
reconcile old ranked candidates against a fresh applicant pool.
