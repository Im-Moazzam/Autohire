# TS-16: Ranked-candidate export

- **Status:** Done
- **Owner:** Moazzam (backend + frontend)
- **Depends on:** US-18/US-19
- **Branch:** `feat/TS-16-candidate-export`

## Why this exists

`docs/api-contract.md` documented `GET /jobs/{id}/candidates/export` as
"defect #8" since early on, and no route, dependency, or UI control for it
ever existed (drift row 74). Recruiters had no way to get a ranked shortlist
out of the app — into a spreadsheet to share, print, or review offline.

## Story

As a recruiter, I want to download the ranked shortlist for a job as a
spreadsheet, so I can share it, print it, or review it outside the app.

## Acceptance criteria

- [x] `GET /jobs/{job_id}/candidates/export?format=csv|xlsx` (default
      `xlsx`) on the existing `job_candidates_router`
      (`backend/app/api/routes/candidates.py`), next to `/candidates/ranked`.
      Ownership via the existing `get_owned_job` dependency — cross-tenant
      404, no new tenant-isolation code needed.
- [x] Ranked candidates only (an `AiAnalysisResult` row must exist) — not
      every submission.
- [x] Column order: `Rank, Name, Email, Phone, Match Score, Status,
      Matched Skills, Missing Skills, AI Feedback`, then one column per
      template field **in template order** (the job's own template — this
      block differs per job by design, drift row 34), then `Submitted At,
      Resume URL`.
- [x] CSV is written with a UTF-8 BOM (`utf-8-sig`) so Excel doesn't mangle
      a non-ASCII candidate name. XLSX via `openpyxl`.
- [x] Bounded at `EXPORT_ROW_CAP` (5000) rows — a file download is not a
      `Page[T]` list (ADR-004 P5's documented-exception mechanism, drift row
      79), but it must still never be an unbounded query (`CLAUDE.md`).
- [x] Filename is built from `job.apply_slug` (already a random token) plus
      a date, with a defence-in-depth character filter — the recruiter-
      supplied `job_title` never reaches the `Content-Disposition` header,
      same discipline `download_resume` already applies.
- [x] Form-response lookup is a single batched query across every exported
      candidate (`candidate_service.responses_by_candidate`), mirroring the
      `ranking_exists_map` precedent (drift row 71) — never N+1 over the
      sheet.
- [x] "Download Excel" link on the AI-ranked tab of `Candidates.tsx`, shown
      when `ranked.data.total > 0`. Plain `<a href>` via the existing
      `resumeHref()` pattern — no blob, no `createObjectURL`, no new fetch
      hook.
- [x] `make api-client` run — `docs/openapi.json`, `frontend/src/lib/api.d.ts`
      and `mobile/lib/api.d.ts` all regenerated and committed.

## Test cases
| ID | Scenario | Expected |
|---|---|---|
| TC-01 | Export CSV for a job with a template that has an extra field | Header matches the documented column order, the template-field block reflects that job's template, row values match the ranked candidate |
| TC-02 | Export XLSX (default format, no query param) | Opens via `openpyxl`, same header order as CSV |
| TC-03 | CSV byte content | Starts with the UTF-8 BOM (`\xef\xbb\xbf`) |
| TC-04 | Response headers | `Content-Disposition: attachment`; a `<script>`-laden job title never appears in the header (filename comes from `apply_slug`, not `job_title`) |
| TC-05 | Cross-tenant export | 404 |
| TC-06 | More ranked candidates than `EXPORT_ROW_CAP` | Export returns exactly `EXPORT_ROW_CAP` rows, not all of them (tested by patching the cap down, not seeding 5000 candidates) |
| TC-07 | `apply_slug` containing unsafe characters | `export_filename` strips them — no `/`, `\`, or space in the result |

## Notes

See `backend/tests/test_export.py` for the full suite. No migration — no new
columns or tables, just a new route and two service functions
(`ranking_service.export_rows`/`build_export_file`,
`candidate_service.responses_by_candidate`). `openpyxl` is a new dependency
(`backend/requirements.txt`) — the de-facto pure-Python xlsx writer, a few
lines at this scale.

The workbook/CSV is built in memory, not streamed —
`# ponytail: in-memory build, stream if a job ever exports >5k rows` is in
`ranking_service.py`. At a single recruiter's job this is tens of rows.

## Out of scope

Exporting raw (non-ranked) submissions — this is the ranked shortlist only,
matching the recruiter-facing need the gap was found against. Streaming for
very large exports. A format other than CSV/XLSX.
