# US-01: Google OAuth sign-up with scope capture

- **Status:** In Review (backend complete; frontend routes are Saif's remaining piece)
- **Epic:** EP-01
- **Points:** 8
- **Backend:** Moazzam · **Frontend:** Saif
- **Depends on:** TS-00

## Story
As a recruiter, I want to sign up using my Google account so that AutoHire can act on
my behalf for Drive, Gmail, and Calendar without me creating a separate password.

## Decided before the session (don't reopen)
- **Session mechanism: signed, HTTP-only, SameSite=Lax cookie.** Not JWT. Single
  server, single frontend origin, no third-party API consumers — a JWT buys nothing
  here and costs refresh/revocation complexity. Use `itsdangerous` or Starlette's
  `SessionMiddleware` with `SECRET_KEY`. If this turns out wrong, changing it later
  touches one dependency and one middleware config, not the data model.
- **Scopes requested: `drive.file`, `gmail.send`, `calendar` — and nothing else** in
  terms of *restricted* scopes. ADR-002: adding a restricted scope later restarts
  Google verification. `openid`, `email`, `profile` are also requested — unrestricted
  identity scopes, required to know who signed in, no verification burden. See
  `docs/drift.md`.
- **OAuth stays in Testing mode** (ADR-002). Refresh tokens expire every 7 days. That
  is expected, not a bug. US-03 handles recovery; this story assumes happy path.

## Acceptance criteria
- [x] `GET /api/v1/auth/google/login` redirects to Google's consent screen with the
      three scopes above, `access_type=offline`, `prompt=consent`, and a signed
      `state` param
- [x] `GET /api/v1/auth/google/callback` validates `state`, exchanges the code, and
      creates a `recruiters` row if none exists for that Google `sub`
- [x] Refresh and access tokens stored encrypted at rest via `TOKEN_ENCRYPTION_KEY`
      (Fernet); token expiry timestamp stored alongside
- [x] New recruiter's `account_state` is `ACTIVE` on first successful auth
- [x] Session cookie set; recruiter redirected to `FRONTEND_URL` dashboard route
- [x] Returning recruiter (existing Google `sub`) logs in, no duplicate row
- [x] Consent denial or Google error redirects to a frontend error route with no
      partial `recruiters` row left behind
- [x] Tokens never appear in any API response body and never in a log line
- [x] `GET /api/v1/auth/me` returns the current recruiter (id, email, name,
      account_state) or 401 — Saif needs this to gate the frontend

## Migration
First real schema migration. Creates `recruiters` only — not the whole ERD. Columns
per `docs/schema.md`, including `account_state` enum (`ACTIVE`, `SUSPENDED`,
`REAUTH_REQUIRED` — matches `docs/schema.md` and `admin_action_enum`; an earlier
draft of this story said `DISABLED`, corrected during implementation) and encrypted
token columns. Everything else comes with its own story.

## Out of scope
Logout and profile edit (US-02). Reconnect flow (US-03). Any real Drive/Gmail/Calendar
call — this story only captures consent. Frontend beyond confirming the redirect lands.

## Prerequisite (do before the coding session)
Google Cloud Console: create project → OAuth consent screen (External, **Testing**) →
add your own Google account as a test user → add the three scopes → create an OAuth
2.0 Web client with redirect URI `http://localhost:8000/api/v1/auth/google/callback`
→ put the client ID and secret in `.env`. Confirm `GOOGLE_CLIENT_ID` and
`GOOGLE_CLIENT_SECRET` exist in `.env.example`; add them if missing.
