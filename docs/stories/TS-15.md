# TS-15: Real LLM analyzer

- **Status:** Done
- **Owner:** Moazzam (backend)
- **Depends on:** US-18/US-19, ADR-003
- **Branch:** `feat/TS-15-llm-analyzer`

## Why this exists

`LocalAnalyzer` was the only `ResumeAnalyzer` implementation. It's canned and
deterministic by design (ADR-003/US-18) — fine for CI and offline dev, but the
product's AI pipeline had no actual LLM in it. This story adds the real
adapter, and in doing so reopens US-18's scoring rule: see ADR-006.

## Story

As a recruiter, I want the AI feedback, matched/missing skills, and ranking to
reflect an actual LLM's judgment of a resume against the job description, not
a keyword-overlap heuristic, so the "AI" in the product does something.

## Acceptance criteria

- [x] `LlmAnalyzer` (`backend/app/adapters/analyzer.py`) implements the
      `ResumeAnalyzer` Protocol via an OpenAI-compatible Chat Completions
      client (`openai` SDK pointed at a configurable `base_url`) — works
      against any free-tier provider exposing that API (Gemini, Grok, Groq,
      OpenRouter, Ollama) without a vendor-specific SDK.
- [x] `ANALYZER` env var selects `local` (default) or `llm`
      (`backend/app/core/config.py`); `LocalAnalyzer` stays the default so CI
      and tests run offline and free.
- [x] LLM response is validated by Pydantic (`_LlmPayload`) before touching
      the DB — `relevance_score` is `Field(ge=0, le=100)`, an out-of-range or
      malformed reply is a `ValidationError`, not a silently clamped number.
- [x] `ResumeAnalysis` gains `relevance_score: int | None`
      (`backend/app/adapters/base.py`) — `None` from `LocalAnalyzer` always,
      an `int` from `LlmAnalyzer` on success, `None` on any failure.
- [x] A failed LLM call (network, rate limit, validation error) degrades that
      candidate to cosine-only scoring — never drops the candidate or aborts
      the batch (preserves US-18 TC-05).
- [x] Rate-limit responses get one bounded retry (`_RETRY_SLEEP_SECONDS`)
      before degrading, rather than failing immediately on a transient 429.
- [x] The resume is explicitly framed as untrusted input in the system
      prompt — any embedded instruction is data to assess, not a command.
- [x] `openai` is an optional dependency: imported lazily inside
      `LlmAnalyzer.__init__`, so `ANALYZER=local` never requires it installed.
- [x] Score blending into `final_score`/`rank_position` and the `match_score`
      API field are **ADR-006**, not this story — TS-15 only produces
      `relevance_score`; ADR-006 is what consumes it.

## Test cases
| ID | Scenario | Expected |
|---|---|---|
| TC-01 | `ANALYZER=local` | `LocalAnalyzer` used, `relevance_score` always `None` |
| TC-02 | `ANALYZER=llm` with valid credentials, well-formed JSON reply | `relevance_score` populated, matched/missing skills and feedback from the model |
| TC-03 | LLM reply fails Pydantic validation (e.g. `relevance_score: 150`) | Degrades to `relevance_score=None`, does not raise into the batch |
| TC-04 | LLM call raises a rate-limit error | One retry after `_RETRY_SLEEP_SECONDS`, then degrade on repeat failure |
| TC-05 | `ANALYZER=llm` with a required setting unset (`LLM_BASE_URL`/`LLM_MODEL`/`LLM_API_KEY`) | `ValueError` at construction, not at analyze-time |
| TC-06 | Resume text contains an injected instruction | Evidence snippets are verbatim resume quotes; system prompt instructs the model to treat it as data |

## Notes

See `backend/tests/test_analyzer.py` for the full adapter test suite and
`docs/decisions/ADR-006-hybrid-scoring.md` for how `relevance_score` is
consumed downstream. No migration here — the scoring columns
(`llm_score`, `final_score`) are ADR-006's migration
(`a1c2e3f4b5d6_add_hybrid_score_columns.py`), and the `LLM` value on
`api_name_enum` for usage logging is
`b2d3f4a5c6e7_add_llm_to_api_name_enum.py`.

## Out of scope

A cloud embedder adapter (still `LocalAnalyzer`'s embedding path per
ADR-003/drift #10). Streaming or multi-turn LLM calls — one request, one
JSON response. A provider-specific SDK or feature (e.g. OpenAI function
calling) — the OpenAI-compatible Chat Completions surface is the lowest
common denominator across the free tiers this project targets.
